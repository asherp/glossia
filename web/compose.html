Read key — share with readers to decrypt (cannot post)
Readers decrypt with the passphrase you set — share it with them separately.
nwrite — keep private; grants posting AND decrypting
npub — the board's public address
How it works. A board lives at an npub derived from its write key (the nwrite). The message is always encrypted — by default with a key derived from that same write key (a hash of the nwrite), then encoded into Glossia prose, signed, and published to public nostr relays. nwrite → post and decrypt; read key → decrypt only; npub → read the prose but not decrypt. Set a passphrase to encrypt with a shared secret instead — readers then decrypt with that passphrase rather than the read key.
Glossia is a readable encoding, not steganography. Encrypted bulletins use authenticated AES-256-GCM, so a wrong key or tampering fails cleanly. The board's signing key has full entropy; a custom passphrase is only as strong as you make it (generated ones target ≥128 bits).
