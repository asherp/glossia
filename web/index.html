How It Works

The encoding pipeline branches into four modalities — decoding reverses the same path

Input bytes | Codec (bit-pack) | Payload tokens | CFG + Montague Types / | \ \ / | \ \ Text Crypto Music Image | | | | Prose Armor Score Colors

Decoding is the same principle for every modality: filter the output against the payload wordlist (or palette, or note set) to recover encoded tokens, then reverse the codec to get the original bytes.

Technical Foundation

Under the Hood

  • WASM-powered: Full Rust engine compiled to WebAssembly — runs entirely in your browser at near-native speed
  • Client-side only: No server, no API calls, no tracking. Your data never leaves your device.
  • Meta-language control: Natural language pipeline specifications with 18 dialect names, 8 verbs, and compactness modifiers
  • 14+ encoders: Text (English, Latin), crypto signatures (PGP, Nostr, NIP-04/44), music (chromatic, pentatonic, blues), and image (8 color palettes)
  • Context-Free Grammars (CFG): Generate grammatically valid sentence structures across all modalities
  • Montague Grammar: Lambda calculus ensures type-safe semantic composition — same types for words, notes, and colors
  • CCG combinators: B, C, T, S, I combinators compose pipelines algebraically
  • POS-based encoding: Payload words fill noun, verb, adjective slots naturally across every modality
  • Adaptive compactness: Length-mode selection and variation generation for optimal word count
  • Merkle-tree wordlists: Cryptographic proofs for wordlist integrity
  • Multi-modal support: English, Latin, Czech, Cryptographic Signatures, Music, Image, and custom dialects
  • Verifiable and reproducible: Inspect the code on GitHub, build it yourself
